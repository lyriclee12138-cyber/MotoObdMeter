## v0.2-beta · 2026-11-08

**实车跑通。接上车上的 OBD，圆屏显示真实转速与水温。**

固件：发送端 `v2026.11.08-165055`、接收端 `v2026.11.03-151123`

> 实车那一次烧的是发送端 `v2026.11.03-144354`，功能与 165055 相同
> （165055 只是把诊断开关关回去、版本号更新，不用重烧）。

### 验证通过的链路

| | |
|---|---|
| 车载 CAN 物理层 | ✅ 500k ISO 15765-4，与 ELM327 报的一致 |
| OBD 数据解码 | ✅ 转速、水温出真实值 |
| 整条链路 | ✅ 供电 → 开发板 → ESP-NOW → 圆屏 |

### 卡了一轮的坑：CANH / CANL 接反

第一次装车：供电正常、设置页显示「发送端 已连接」、CAN 状态「无数据」，但一帧都收不到。

用 `CAN_DIAG_MODE=1` 的诊断固件逐层切开，每一步都排掉一类可能：

| 步骤 | 结果 | 排掉了什么 |
|---|---|---|
| RX 线连通性（切内部上下拉） | 外部强驱动 | 模块没电、芯片坏、杜邦线松 |
| TX 通路（NO_ACK 自发看位错误） | 位错误 0 | TX 线断 |
| ACK 测试（发 0x6A5 看有没有人应答） | 无应答 | 总线上没有其他节点 |
| 四档速率监听 | 全 0 帧 | 速率不匹配 |

四项都指向"总线是空的"，但线明明接着。最后按诊断提示**把 CANH/CANL 对调**——好了。

**为什么这个故障这么隐蔽**：CAN 是差分信号，`CANH−CANL > 0.9V` 才算显性位。
接反后差分变负，收发器把负值也判为隐性 → 整条总线看起来一直空闲 →
RX 恒高、`rx_err` 恒 0、四个速率全 0 帧。这和"两根线悬空"的读数**完全一致**，
软件层面无法区分。**接反不会烧任何东西，但对调这一步只能人工做。**

诊断固件最后一条提示就是「CANH/CANL 对调再试」，答案是它给的。

### 遗留

- **数值准不准还没核对**（圆屏转速 vs 仪表读数、水温 vs 实际）
- 车载 ACC 取电还没实际接（目前还是充电宝）
- 长期稳定性未知（丢包、重启、屏幕残影）

### 这一版修掉的结构性问题（详见 docs/dev-guide.md 第 8 节）

1. **发送端启动卡死**：DEBUG 优化导致卡在 CPU1 启动 → 改 PERF 优化
2. **改完 PERF 立刻 panic**：崩在 PSRAM 初始化 → 关闭 PSRAM（发送端不需要 8MB）
3. **黑夜模式翻页时四角发白**：`png2c.py` 把透明像素合成到白色 → 按主题底色合成
4. **转速弧颜色错乱**（两次）：根因不是颜色算错，而是"增量重绘 + 运行时算色"。
   最终改成**整条彩环烘焙进背景图**，运行时只负责擦掉未填充部分
5. **弧中间断一截**：脏区起点按"上一帧值"算，慢速爬升时起点漂移，漂过的那段
   从来没画过 → 改为记录"屏幕上实际画到哪了"
6. **0 转时留一个绿点**：烘焙的起点圆头比擦除弧探出 1.7° → 两端都不烘焙圆头
7. **未填充段边缘透色**：擦除弧与彩环同尺寸，半像素错位擦不干净 → 擦除弧宽 1px

### 未验证

- **实车 CAN 数据**（接上 OBD 才有真实转速/水温）
- 车载 12V 取电（现在还是充电宝供电）
- 圆屏没有休眠逻辑，长期挂车上要注意

### 已知取舍

- 仪表页的金属质感/刻度是**离线烘焙的背景图**，改配色要重新渲染素材
- 设置页滚动会吃掉横向手势？不会——`scroll_dir` 只允许垂直，两者天然互斥
- 发送端深睡时收发器仍处在高速模式（约 10mA），是静态耗电的主要来源，
  后续可以用 Rs 引脚待机把它压下去
