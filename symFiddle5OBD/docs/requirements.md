## 2. 项目背景

三阳飞度 5 是一台国四踏板车，原车仪表信息有限。车主希望在不改动原车的前提下，
**读取 ECU 的骑行数据并在车把处用一块圆屏仪表展示**（转速、水温），
实现类似大排量车型的电子仪表体验。

经实车确认（2026-10-30/31），该车诊断口为 **16 针 OBD-II**（座桶后、电池上方），
协议为 **ISO 15765-4 CAN（11 bit ID，500 kbaud）**，ECU 名 `ECM-EngineControl`，
自报 EOBD (Europe)。这使整条技术路线从「逆向私有 K 线协议」大幅简化为
「标准 OBD PID + CAN 物理层」，可行性显著提升。

---

## 3. 项目目标

1. 从 OBD-II 口稳定读取 **发动机转速（RPM）** 与 **冷却液温度（CLT）**。
2. 通过低延迟无线链路把数据送到车把处的 **466×466 圆屏**。
3. 圆屏以高可读性的「大数字 + 转速弧 + 水温」形式实时展示。
4. 提供日间 / 夜间两套配色与可交互的设置页。
5. 支持装车后的车载供电与长期稳定运行。

---

## 4. 范围

### 4.1 范围内（In Scope）

- CAN 物理层（TWAI 500 kbaud）与 ISO-TP / OBD PID 解析
- ESP-NOW 单向数据传输 + 接收端心跳回传
- 圆屏仪表界面（转速弧、转速数字、水温、红区警示）
- 日/夜主题切换与设置页
- 发送端状态指示、演示模式、深度睡眠
- 车载供电（ACC 取电）方案与接线

### 4.2 范围外（Out of Scope）

- **车速显示**：实测 PID 0x0D 无响应，轮速信号直连原车仪表、不进 ECU，已明确放弃
- 燃油量、电压等其他仪表数据（部分 PID 该车不支持）
- 手机 App / 云平台 / 数据记录回放
- 逆向私有协议或刷写 ECU

### 6.1 遥测数据契约

发送端与接收端之间通过 23 字节的 `telemetry_t` 结构通信（定义于
`firmware/common_components/shared/telemetry.h`）：

```
magic + version + seq + flags + rpm + clt
```

- `magic` / `version`：接收端校验，不匹配则拒收
- `seq`：丢包检测
- `flags`：含 `TF_RPM` 等数据有效标志位（CAN 有数据时才置位）

> 协议改动必须两端同步，否则表现为「收包数恒 0」。

| 部件 | 型号 / 规格 | 角色 | 备注 |
|---|---|---|---|
| 发送端开发板 | ESP32-S3 N16R8（16MB Flash / 8MB PSRAM） | CAN 采集 + ESP-NOW 发送 | PSRAM 已关（不需要） |

### 8.1 关键接线（速查）

| 信号 | 接点 |
|---|---|
| TWAI_TX | ESP32-S3 GPIO4 → 模块 TX/CTX/D |
| TWAI_RX | ESP32-S3 GPIO5 → 模块 RX/CRX/R |
| CANH | 模块 CANH → OBD 6 脚 |
| CANL | 模块 CANL → OBD 14 脚 |
| 地 | 模块 GND → OBD 4（电源）/ 5（信号）脚 |

## 9. 界面需求

详见 `docs/UI规格-beta.html`（已锁定基线）。核心规格：

- **屏幕**：466×466 圆形，所有内容收敛在半径 ~225 内

## 10. 约束与假设

- 发送端与接收端均在 **ESP-IDF v5.x** 上构建（本机 5.5.5 实测通过）。
- 两端 Flash 容量不同（接收端 32MB / 发送端 16MB），烧录参数**不可混用**。
- CANH/CANL 为差分信号，**接反不会损坏但完全收不到数据**，且症状与「未接线」一致，只能人工对调。
- 里程 PID 0x31 会在清故障码后归零，需 offset 补偿。

## 11. 验收标准

| 项 | 通过标准 |
|---|---|
| 数据链路 | 实车接入 OBD 后，圆屏显示与 ELM327 一致的转速 / 水温 |
