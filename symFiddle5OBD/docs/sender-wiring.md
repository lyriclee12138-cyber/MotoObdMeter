# 发送端接线与联调（第一版）

> 目标：**先不考虑车上供电**，用充电宝插 USB-C 给开发板供电，把「CAN 收数 → ESP-NOW → 圆屏显示」跑通。
> 真正装车（12V 取电、ACC 控制、休眠）留到下一阶段。
> 对应固件：`firmware_out/fiddle5_sender_<时间戳>_full.bin` + `fiddle5_receiver_<时间戳>_full.bin`（同一版本串）

---

## 1. 三件设备分别是什么

| 设备 | 在链路里的角色 |
|---|---|
| ESP32-S3 开发板（双 USB-C，N16R8） | 主控。跑发送端固件，TWAI 控制器 + ESP-NOW 都在它里面 |
| SN65HVD230 模块（3.3V 版） | 电平转换。把 ESP32 的 3.3V 逻辑 CAN 变成车上的差分 CAN（CANH/CANL） |
| 白色 16 针 OBD 公头带尾线 | 插到坐桶后那个诊断口，把车上的 CANH/CANL/地引出来 |

开发板上有**两个 USB-C**：

- 标 **COM / UART** 的那个 → 走板载 USB 转串口芯片。**烧录和看日志都插这个**，自动复位可靠。
- 标 **USB** 的那个 → 芯片原生 USB（GPIO19/20）。能用，但看日志要特殊处理（DTR/RTS 都得是 False），按项目里的老记录，容易误判成"板子死了"。

供电结论：**充电宝插 COM 口就行**，一根线同时解决供电和串口。

---

## 2. 接线表

一共只有 7 根线。其中 5 根在桌面就能接，2 根上车才接。

### 2.1 模块 ↔ 开发板（桌面接）

| SN65HVD230 | 开发板 | 说明 |
|---|---|---|
| 3.3V / 3.3U / VCC | **3V3** | ⚠️ 只能 3.3V。这模块接 5V 会烧 |
| GND | **GND** | 任一 GND 针都行 |
| TX / CTX / D | **GPIO4** | 模块的"发"，接 ESP32 的 CAN_TX |
| RX / CRX / R | **GPIO5** | 模块的"收"，接 ESP32 的 CAN_RX |
| RS / STB / S（若有） | **GND** | 接地下才是高速模式；悬空会进待机，完全不通 |
| Vref（若有） | 悬空 | 不用 |

**不要交叉 TX/RX。** 这是最容易搞错的点：UART 要交叉，CAN 收发器**不交叉**——
模块上的 TX 就是"驱动器输入（D）"，RX 就是"接收器输出（R）"，照名字对名字接。
（网上很多教程写"模块 TX 接 MCU RX"，那是另一个型号的接法，别照抄。）

### 2.2 模块 ↔ OBD 接头（上车接）

| 模块 | OBD 16 针 | 说明 |
|---|---|---|
| CANH | **6** | ISO 15765-4 标准位置 |
| CANL | **14** | 同上 |
| GND（模块或板子的 GND） | **4 或 5** | **必须接**，否则 CAN 没有共地参考，收不到任何帧 |

CANH / CANL 这两根**要双绞**（互相绕在一起），长度尽量短（<30cm）。

### 2.3 电源

```
充电宝 ──USB-C──> 开发板（COM 口）
                    └── 3V3 ──> 模块 3.3V
                    └── GND ──> 模块 GND
```

OBD 的 **16 脚（+12V 常电）这一阶段不接**，线头单独用胶带包好。
不接车的 12V，就没有"把电瓶耗干"和"12V 窜进 3.3V"的风险。

## 3. 白色接头怎么核对针号（关键一步）

尾线的**颜色没有任何标准**，厂家每批都可能换。千万不要按颜色猜，必须实测。
J1962 接头面向**针脚那一面**看：上排 1–8（左→右），下排 9–16（左→右），
接头上有模压的小数字，多数能直接看清。

三步确定 5 根线：

1. **认针号**：对着模压数字，把每根线在胶带上标出针号（1…16）。
2. **找 16 脚（常电）**：万用表直流电压档，黑笔搭车体/电瓶负极，红笔依次碰线尾。
   钥匙关闭状态下仍是 **12.5V 左右**的那根就是 16。
3. **找 4/5 脚（地）**：通断档（或电阻档），与车体/电瓶负极**导通（<1Ω）**的是 4 或 5，任选一根用。
4. **剩下两根信号线就是 6 / 14**：确认方法是钥匙打到 ON（不启动发动机），
   两线之间电阻约 **60Ω**（车内两个 120Ω 终端电阻并联）；对地电压都在 2.5V 附近。

**分不清 6 和 14 也没关系**：CANH/CANL 接反不会烧任何东西，只是收不到帧。
上电看日志如果 3 秒嗅探是 0 帧，把这两根对调再试——这是最快的判定方法。

其余线（K-line 7/15、厂商自定义等）**全部单独包好**，不要让它们互相碰到。

## 4. 电气注意事项（都是会烧东西的）

1. **模块只能接 3.3V**。SN65HVD230 的绝对最大供电是 6V，接 5V 会直接损坏。
2. **不要同时插 USB 和车上 12V**（下一阶段装车时才相关）。板子的 5V 针和 USB 的 5V 是连通的，两路电源会互相灌。
3. **CANH/CANL 不要接 12V 或地**。虽然模块有 ESD 保护，但持续短路会烧收发器。
4. **终端电阻：不要加**。车上本来就有两个 120Ω，我们只是第三个节点。
   先测一下模块 CANH–CANL 之间的电阻（不上电、不接线）：应该是 **开路（>1kΩ）**。
   如果是 120Ω 说明板上焊了终端电阻（有些模块带跳线帽），**要断开**，否则总线阻抗不匹配。
5. 插拔 OBD 接头时**先关钥匙**。发动机运转时插拔会有瞬态，没必要冒这个险。
6. 接车测试时**先断电池负极**再动线（装车阶段）。

## 5. 分阶段联调

### 阶段 A · 桌面（不接车，只插充电宝）

1. 按 2.1 接好 5 根线，**不接** OBD 那两根。
2. 烧 `fiddle5_sender_<时间戳>_full.bin`（地址 0x0，Flash 16MB）。
3. 串口 115200 看日志，应该出现：

```
I (xxx) main: === Fiddle5 OBD sender (CAN / ISO 15765-4) ===
I (xxx) main: 固件版本 v2026.11.02-xxxxxx（编译于 ...）
I (xxx) main: 接线核对: 模块3.3V->3V3  GND->GND  TX->GPIO4  RX->GPIO5  CANH->OBD6  CANL->OBD14
I (xxx) can: TWAI up @500k  TX=GPIO4 RX=GPIO5
W (xxx) main: 总线上 3 秒内一帧都没收到
W (xxx) main:   只插了充电宝、没接车 -> 正常，可以继续
I (xxx) uplink: ESP-NOW ready, ch=1, bcast
I (xxx) main: rpm=0 clt=0 tps=0 v=0.0 odo=-- run=0min flags=0x0080
```

`flags=0x0080` 表示只有"运行时长"有效，其余全无 —— 这就是没接车时的正确状态。

### 阶段 B · 两块板桌面对联（验证 ESP-NOW 和屏）

1. 圆屏烧同一版本的 `fiddle5_receiver_<时间戳>_full.bin`（Flash **32MB**）。
2. 两块板都上电。圆屏此时应该：仪表显示 `--`，设置页「发送端 = 未连接」。
3. **按住发送板上的 BOOT 键 1 秒以上**。串口会出现：

```
W (xxx) main: == 进入模拟数据模式：上行发假数据，仅用于验证 ESP-NOW/屏幕 ==
```

圆屏应该在 1 秒内开始扫表（转速 1450 → 9200 来回），设置页变成「已连接」（绿点）。

**这一步过了，说明 ESP-NOW、协议版本、屏幕链路全部正常**，后面出问题就只在 CAN 侧。

4. 松开 BOOT 即退出模拟模式，圆屏回到 `--`。

> 模拟模式是"按住才生效、松手就退出"的，不会因为误触把假数据一直发出去。
> 注意**复位时**按住 BOOT 会进下载模式、程序不跑——那是芯片的机制，和这里无关。

### 阶段 C · 接车（先只收，不发请求）

1. 钥匙关闭，把 CANH/CANL/GND 接到 OBD 6/14/4（或 5）。
2. 钥匙打到 ON（**先不启动发动机**——飞度 5 的 ECU 上电就会发周期性帧）。
3. 看串口前 3 秒的嗅探结果：

```
I (xxx) can:   <- id=0x0C0 dlc=8  ...
I (xxx) main: 总线物理层 OK：3 秒收到 128 帧
I (xxx) can:   ID 列表: 0x0C0 0x1A0 ...
```

**有帧 = 物理层全对**。这一步不需要发任何请求，是判定的黄金标准。

一帧都没有，按这个顺序查：CANH/CANL 对调 → 共地有没有接 → 钥匙是不是真的 ON。

### 阶段 D · 全链路

总线通了之后，固件会自动开始轮询 PID，10 秒一行状态：

```
I (xxx) main: rpm=1726 clt=83 tps=12 v=14.1 odo=11582.0km run=12min flags=0x00EF
```

`flags` 期望值 **0x00EF**（RPM+水温+节气门+进气+电压+里程+运行时长），
油量位（0x0010）永远不会亮 —— 这台车的 ECU 不支持 PID 0x2F，是已知事实。

圆屏同时应该显示转速和水温。

## 6. 故障对照

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 串口完全没日志 | 插的是 USB 口（原生 USB）而不是 COM 口；或线只能充电 | 换 COM 口 / 换数据线 |
| 反复 `bus-off detected` | CANH/CANL 接反，或共地缺失 | 对调两根线、接好 GND |
| 3 秒嗅探 0 帧，但钥匙是 ON | 没共地（最常见）；或接头针号认错 | 先量 4/5 脚与车体的通断 |
| 有帧，但 `flags` 一直 0x0080 | 只收到帧、没收到诊断响应 | 看有没有 `PID 0xXX not supported`；确认是 0x7DF 还是 0x7E0 |
| 圆屏一直 `未连接` | 两块板不同信道；或接收端还是旧固件（没有 ESP-NOW） | 都烧同一版本固件 |
| 圆屏设置页版本号没变 | 固件没烧进去 | 用 full 包从 0x0 重烧，Flash 大小填对 |
| 通话正常但偶尔跳 `--` | 距离/干扰；或发送端被 60 秒静默休眠 | 阶段 A 没接车时是 10 分钟才睡，接车后是 60 秒 |

## 7. 下一步（跑通之后才做）

1. **供电上车**：OBD 16 脚 → 2A 保险丝 → 9–36V→5V 3A 降压 → 板 5V 针。
   降压模块静态电流要 <1mA，否则停一周电瓶就亏。
2. **ACC 控制**：16 脚是常电，必须接到受钥匙控制的那一路，或依赖固件深睡（已实现）。
3. **线束**：CANH/CANL 双绞、加磁环、接头做防水；开发板换洞洞板/自制 PCB 固定。
4. **休眠实测**：接车后确认熄火 60 秒进入深睡、5 分钟醒来探一次总线，整机静态电流 <5mA。
