# symfiddle_sender — 发送端固件

三阳飞度 5 摩托车的 OBD 数据采集端。跑在 ESP32-S3 N16R8 开发板上，
通过 CAN 读取 ECU 数据，经 ESP-NOW 广播给车把上的圆屏。

**协议已实测确认**：ISO 15765-4 CAN，11 bit ID，500 kbaud，ECU 名 `ECM-EngineControl`。

## 接线

**完整版（含针脚核对方法、电气红线、分阶段联调、故障对照）见
[`docs/sender-wiring.md`](../../docs/sender-wiring.md)。** 这里只留速查表。

### CAN 侧（SN65HVD230 3.3V 模块）

| 模块引脚 | 接到 |
|---|---|
| 3.3V / 3.3U / VCC | 开发板 **3V3** ⚠️ 只能 3.3V，5V 会烧模块 |
| GND | 开发板 GND |
| TX / CTX / D | ESP32-S3 **GPIO4**（TWAI_TX） |
| RX / CRX / R | ESP32-S3 **GPIO5**（TWAI_RX） |
| RS / STB（若有） | **GND**（高速模式，悬空会进待机） |
| Vref（若有） | 悬空 |
| CANH | OBD **6 脚** |
| CANL | OBD **14 脚** |
| 模块 GND | OBD **4 或 5 脚**（必须共地） |

**TX/RX 不交叉**：模块的 TX 是驱动器输入（D），RX 是接收器输出（R），照名字对名字接。
CANH / CANL 必须**双绞**，长度 <30cm。模块上的 120Ω 终端电阻**不要接**（车上已有两个）。

### 供电（第一阶段：充电宝）

```
充电宝 ──USB-C（COM 口）──> 开发板 ──3V3──> SN65HVD230
```

OBD 16 脚（+12V 常电）**这一阶段不接**，线头包好。

装车阶段再改成：`OBD 16 脚 → 2A 保险丝 → 9–36V→5V 3A 降压 → 板 5V`，
并加 `SMBJ18A` 反向保护。⚠️ 任何时候都**不要同时插 USB 和 12V**。

## 编译与烧录

出手机可烧的包（推荐，会带上版本号和烧录说明）：

```bash
./tools/win/pack_firmware.sh sender     # 只出发送端；both = 收发两端一起
```

产物在 `firmware_out/`，`*_full.bin` 从 **0x0** 烧，Flash 填 **16MB**。

手工编译：

```bash
cd firmware/sender
./../../tools/win/idf.bat -B build build
```

需要 ESP-IDF **5.1 以上**（本机 5.5.5 实测通过，`driver` 是 meta 组件）。

自定义分区表 `partitions.csv`：factory 给到 **4MB**（默认的单 app 只有 1MB，
当前固件 0.74MB 就快顶到了）。改这张表会清 NVS，趁没上过车改最省事。

## 上电自检与模拟模式

固件里有两个专门为"第一次上板"准备的东西：

1. **上电嗅探 3 秒**：TWAI 起来后先被动听 3 秒，把所有收到的帧打到日志。
   这一步不发任何 OBD 请求，只看物理层通不通 —— 有帧就是接线/共地/波特率全对。
2. **BOOT 键模拟数据**：开机后**按住 BOOT 键 1 秒**（不是复位时按，那样会进下载模式），
   进入模拟模式，上行改发 20 秒循环的假数据（1450→9200 rpm）。
   用来在两块板子只有充电宝的情况下验证「ESP-NOW → 圆屏」整条链路。
   松手立即恢复真实数据。

另外：开机后**一次总线都没见过**时，深睡超时从 60 秒放宽到 10 分钟，
避免台架调试时板子突然睡过去。见过总线（接过车）之后仍然按 60 秒。

## 预期串口输出

正常启动：

```
I (312) main: === Fiddle5 OBD sender (CAN / ISO 15765-4) ===
I (313) main: 固件版本 v2026.11.02-150951（编译于 2026-11-02 15:09）
I (313) main: 接线核对: 模块3.3V->3V3  GND->GND  TX->GPIO4  RX->GPIO5  CANH->OBD6  CANL->OBD14
I (312) can: TWAI up @500k  TX=GPIO4 RX=GPIO5
W (3312) main: 总线上 3 秒内一帧都没收到        ← 没接车时正常
I (321) runtime: 无历史运行时长，从 0 开始
I (455) uplink: ESP-NOW ready, ch=1, bcast
I (462) obd: poller ready, 7 tasks
```

每 10 秒一次状态行：

```
I (10462) main: rpm=1726 clt=83 tps=12 v=14.1 run=0min flags=0x00A7
```

`flags` 的位定义见 `telemetry.h`。**如果 flags 一直是 0x0000，说明一个 PID 都没读通**，
先查接线和总线电平，别急着怀疑代码。

### 排障对照

| 现象 | 最可能的原因 |
|---|---|
| 完全没有日志输出 | 供电问题。别插着 12V 又插 USB |
| `TWAI up` 之后一直没有状态行 | 卡在等响应。把日志级别调到 DEBUG 看有没有收到任何帧 |
| 反复 `bus-off detected` | CANH/CANL 接反，或终端电阻问题 |
| `PID 0x2F not supported` | 这个 ECU 不提供油量（踏板车多为浮子直连仪表），正常 |
| `PID 0x42 not supported` | **本车实测预期就是这个**。App 上的「OBD 模块电压 14V」是 ELM327 自测，不是 ECU 数据。要显示电压需硬件分压进 ADC |
| `里程回落 xx km，判定为清码` | 有人清了故障码。补偿会自动接上，显示值不会倒退 |
| `功能寻址无应答，切换到物理寻址` | 正常现象，很多 ECU 只答 0x7E0 |

## 代码结构

| 文件 | 职责 |
|---|---|
| `can_link.c` | TWAI 装驱动、收发帧、**bus-off 自愈**、上电嗅探 |
| `isotp.c` | ISO 15765-2 分帧重组（纯 C） |
| `decode.c` | PID 公式解码（纯 C） |
| `obd_poll.c` | 轮询调度、寻址方式自动切换 |
| `odo.c` | 里程（PID 0x31）+ 清码回落补偿 + NVS 持久化 |
| `runtime.c` | 发动机运行时长计时 + NVS 持久化 |
| `uplink.c` | ESP-NOW 广播 |
| `app_power.c` | 总线静默 60s 后深度睡眠，每 5 分钟唤醒探测（从未见过总线时 10min）|
| `version.c` | 版本串，由 pack_firmware.sh 每次出包重写 version_env.h |
| `main.c` | 主循环 |

## 车速：ECU 认识这个 PID，但恒返 0

2026-10-31 实测两轮：

1. 发动后有转速、无车速；手动转前轮时**原车仪表有反应、手机端无数据**。
2. 后来拿到完整传感器页，`车速` 一栏显示的是 **0 km/h 而不是「无数据」**。

第 2 点修正了此前的判断：ECU **会应答** 0x0D，只是返回值恒为 0——轮速
信号确实没进 ECU。这不改变结论（这个数没法用），但解释清楚了机制。

`obd_poll` **不轮询 0x0D**：读到的 0 不能显示，显示 0 km/h 会让骑手误判
为停车，比显示 `--` 更危险。项目也不接轮速传感器。

## 里程：PID 0x31 救回来了

里程 = 速度对时间积分，速度源没了本来积不出来。但标准 PID `0x31`
（Distance traveled since codes cleared）实测返回 **11582 km**，与表显
里程同一量级。只要不清故障码，它就等于里程，对保养提醒完全够用。

**唯一的坑是清码归零**——真发生的话里程会从 11582 跳成 1，比不显示更糟。
`odo.c` 用 offset 补偿处理：

- 新读数比上次低 50 km 以上 → 判定为清码，把差额累加进 `offset`
- 显示值 = ECU 值 + offset，保证单调不减
- `offset` 与历史最大值都存 NVS，**跨重启也有效**（这也是为什么 NVS 里
  额外存了一个 `raw` 键：只存显示值的话，上电首次读数没法判断是否回落）

降级路径：0x31 被否定响应 → 改试非标准 `0xA6` → 两者都不行则
`TF_ODO` 不置位，界面显示 `--`。

同时保留**发动机运行时长**作为第二基准。运行小时数在工程机械和商用车上
本来就是标准保养依据——机油劣化取决于运转时间和热循环，跟走了多少公里
关系没那么大。而且它熄火不积分，不会被推车挪车干扰。

## 运行时长怎么重置

运行时长存在 NVS 分区（命名空间 `symrun`，键 `min`）。做完保养想清零：

```bash
idf.py erase-flash && idf.py flash
```

注意这会连 Wi-Fi 配置一起清掉，反正本工程也不存别的。掉电最多损失
30 分钟（每 30 分钟落盘一次）。
